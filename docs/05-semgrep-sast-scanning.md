# ৫. Semgrep দিয়ে SAST স্ক্যানিং

> Semgrep ইনস্টলেশন, CLI স্ক্যানিং, এবং Manual vs SAST vs AI কোড রিভিউ তুলনা।

## Semgrep CLI দিয়ে পুরো ফোল্ডার স্ক্যান

### **Semgrep কীভাবে ইনস্টল করবেন?**

Semgrep মূলত একটি কমান্ড-লাইন টুল। এটি ইনস্টল করা খুবই সহজ। আপনার টার্মিনালে
অপারেটিং সিস্টেম অনুযায়ী নিচের যেকোনো একটি পদ্ধতি ব্যবহার করতে পারেন:

**Linux বা Windows WSL বা Codespaces-এর জন্য:**

```bash
python3 -m pip install semgrep
```

(এটি পাইথনের প্যাকেজ ম্যানেজার pip দিয়ে Semgrep ইনস্টল করবে।)

**Mac (macOS)-এর জন্য:**

```bash
brew install semgrep
```

ইনস্টল হয়ে গেলে টার্মিনালে semgrep --version লিখে চেক করতে পারেন টুলটি
ঠিকমতো ইনস্টল হয়েছে কি না।

### **ধাপ ২: Semgrep CLI দিয়ে স্ক্যানিং এবং বিস্তারিত তুলনা (৭৫--৯০ মিনিট)**

**কীভাবে স্ক্যান চালাবেন:** টার্মিনালে আপনার প্রজেক্টের ফোল্ডারে (যেখানে
introduction ফোল্ডারটি আছে) গিয়ে নিচের কমান্ডটি দিন:

```bash
semgrep scan --config="p/django" --config="p/python" introduction/
```

*(এই কমান্ডটি Semgrep-কে বলছে: "আমার introduction/ ফোল্ডারের ভেতর ড্যাঙ্গো
(p/django) এবং পাইথন (p/python) এর যত সিকিউরিটি রুল বা চেকলিস্ট আছে, সেগুলো
ধরে স্ক্যান করো।")*

**কী দেখাবেন (স্ক্যানের ফলাফল ও বিশ্লেষণ):**

-   **দ্রুততম স্ক্যানিং:** Semgrep মাত্র কয়েক সেকেন্ডের মধ্যে পুরো
    introduction/views.py ফাইলটি পড়ে ফেলবে।

-   **কী খুঁজে পাবে:** এটি আপনার কোডে থাকা objects.raw(...) লাইনটি খুঁজে
    বের করবে এবং টার্মিনালে লাইন নম্বরসহ ওয়ার্নিং দেখাবে যে--- এখানে "Raw
    SQL" এবং "String Concatenation (ফরম্যাট স্ট্রিং বা + চিহ্ন দিয়ে ইনপুট
    জোড়া লাগানো)" ব্যবহার করা হয়েছে, যা SQL Injection-এর ঝুঁকি তৈরি করে।

**গুরুত্বপূর্ণ তুলনা (Manual vs SAST vs AI):** এই ধাপে স্টুডেন্টদের তিনটি পদ্ধতির
(ম্যানুয়াল, টুলস এবং এআই) শক্তির জায়গা ও দুর্বলতা বোঝাতে হবে:

-   **SAST (Semgrep) এর সুবিধা:** Semgrep খুব সহজেই ধরা-বাঁধা নিয়ম বা রুলস
    অনুযায়ী objects.raw() বা সরাসরি eval() ফাংশনের মতো পরিচিত বিপজ্জনক
    প্যাটার্নগুলো ধরে ফেলতে পারে।

-   **SAST (Semgrep) এর দুর্বলতা (False Negative):** ssti_lab-এ ডেভেলপার
    যে ইনপুট ফিল্টার করার জন্য filter_blog() ফাংশন বানিয়েছে, কিন্তু ভেতরে
    কোনো কোড না লিখে শুধু pass লিখে ফাঁকা রেখেছে--- Semgrep এর মতো সাধারণ
    SAST টুল এই ধরনের লজিক্যাল ভুল বা বিজনেস লজিক বাগগুলো ধরতে পারে না।
    টুলটি ভাবে যেহেতু একটি ফাংশন দিয়ে ডেটা পাস করা হচ্ছে, তার মানে এটি
    নিরাপদ হতে পারে।

-   **Manual ও AI এর শ্রেষ্ঠত্ব:** যেখানে টুলস লজিক্যাল ভুলে আটকে যায়, সেখানে
    মানুষের ব্রেন (ম্যানুয়াল কোড রিভিউ) বা AI (যেমন ChatGPT/Copilot) সহজেই
    পুরো কোডের পেছনের লজিক বুঝতে পারে এবং ধরিয়ে দিতে পারে যে পাহারাদার
    বা গার্ড ফাংশনটি আসলে কোনো কাজ করছে না।

## Semgrep CLI-তে কী কী কমান্ড ব্যবহার করা যায় এবং সেগুলো বের করার উপায়

django বাদে অন্যান্য ফ্রেমওয়ার্ক বা ভাষার জন্য Semgrep CLI-তে কী কী কমান্ড
ব্যবহার করা যায় এবং সেগুলো বের করার উপায় নিচে বিস্তারিতভাবে দেওয়া হলো:

### **অন্যান্য ফ্রেমওয়ার্ক বা ভাষার জন্য Semgrep স্ক্যান কমান্ড**

Semgrep-এ স্ক্যান চালানোর সময় `--config` ফ্ল্যাগের মাধ্যমে কোন রুলসেট (Ruleset)
ব্যবহার করতে চান তা নির্দিষ্ট করে দিতে হয়। নিচে কয়েকটি জনপ্রিয় ভাষা ও
ফ্রেমওয়ার্কের জন্য উদাহরণ দেওয়া হলো:

**Node.js / Express / JavaScript / TypeScript-এর জন্য:**

```bash
semgrep scan --config="p/nodejs" --config="p/javascript" --config="p/typescript" ./your_project_folder/
```

**Python / Flask / FastAPI-এর জন্য:**

```bash
semgrep scan --config="p/python" --config="p/flask" --config="p/fastapi" ./your_project_folder/
```

*(নোট: শুধু `p/python` দিলে পাইথনের সাধারণ বাগ ধরবে, আর `p/flask`
দিলে স্পেসিফিকভাবে Flask-এর `debug=True` বা `eval`-এর মতো সমস্যা ধরবে।)*

**Java / Spring-এর জন্য:**

```bash
semgrep scan --config="p/java" --config="p/spring" ./your_project_folder/
```

**Go (Golang)-এর জন্য:**

```bash
semgrep scan --config="p/golang" ./your_project_folder/
```

**Ruby / Ruby on Rails-এর জন্য:**

```bash
semgrep scan --config="p/ruby" --config="p/ruby-on-rails" ./your_project_folder/
```

**সব ধরনের সিকিউরিটি রুল একসাথে চালানোর জন্য (যেকোনো ভাষার জন্য):**
আপনি যদি নির্দিষ্ট ভাষার নাম না জানেন, তবে Semgrep-এর ডিফল্ট বা
জনপ্রিয় সব সিকিউরিটি রুল একসাথে চালাতে পারেন:

```bash
semgrep scan --config="p/default" --config="p/security-audit" ./your_project_folder/
```

*(তবে এটি অনেক সময় নিবে এবং অনেক বেশি False Positives দিতে পারে।)*

### **আপনার প্রয়োজনীয় রুল বা কমান্ড কীভাবে খুঁজে বের করবেন?**

আপনি যদি নতুন কোনো ফ্রেমওয়ার্ক (যেমন: React, Laravel, বা C#) নিয়ে কাজ করতে
যান এবং তার জন্য সঠিক `--config` নামটি জানতে চান, তবে নিচের ৩টি উপায়
ব্যবহার করে তা বের করতে পারেন:

**১. Semgrep Registry ওয়েবসাইট থেকে (সবচেয়ে সহজ উপায়):**

-   Semgrep-এর অফিশিয়াল রুলস ওয়েবসাইটে যান: <https://semgrep.dev/explore>
-   সেখানে সার্চ বক্সে আপনার ফ্রেমওয়ার্ক বা ভাষার নাম (যেমন: react, express,
    php) লিখে সার্চ করুন।
-   সার্চ রেজাল্টে আসা রুলপ্যাকগুলোতে ক্লিক করলেই ডানপাশে ব্যবহারের কমান্ডটি
    (যেমন: `semgrep --config "p/express"`) লেখা দেখতে পাবেন।

**২. কমান্ড লাইন (CLI) থেকে সাহায্য নেওয়া:** টার্মিনালে সরাসরি নিচের
কমান্ডটি লিখলে এটি আপনাকে দেখাবে কীভাবে রুল ব্যবহার করতে হয়:

```bash
semgrep scan --help
```

**৩. গিটহাব (GitHub) সার্চ ট্রিক ব্যবহার করে:** আপনি যদি স্পেসিফিক কোনো
দুর্বলতার (যেমন: SQL Injection) রুল খুঁজতে চান, তবে গিটহাবে গিয়ে `semgrep sql
injection rules` লিখে সার্চ করতে পারেন। সিকিউরিটি রিসার্চাররা তাদের বানানো
অসংখ্য কাস্টম YAML রুল সেখানে আপলোড করে রাখেন। আপনি চাইলে সেই ফাইলটির পাথ
বা URL সরাসরি কমান্ডে ব্যবহার করতে পারেন:

```bash
semgrep scan --config="https://raw.githubusercontent.com/user/repo/rule.yaml" ./your_project_folder/
```
